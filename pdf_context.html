1. Problem Statement & Motivation

Traditional event management platforms suffer from four critical architectural and usability flaws:

The Friction in Existing Solutions
  • Mandatory Account Walls: Forcing casual attendees to create passwords and verify accounts leads to over 40% checkout abandonment.
  • High Infrastructure Costs: Persistent 24/7 cloud servers (AWS EC2, Railway, Render) incur monthly fees even when no events are active.
  • Check-in Bottlenecks: Manual paper lists cause long door queues, and static PDF passes permit duplicate entry fraud.
  • Rigid Form Schemas: Event organizers cannot ask custom questions without modifying database tables.
The EventHub Solution
  • Zero-Login Guest RSVP: Attendees enter Name, Email, and dynamic answers in 15 seconds with zero password friction.
  • 100% Serverless on Vercel: Runs as on-demand Python ASGI Lambdas with zero idle cost ($0 per month).
  • Sub-Second Camera Scanner: WebRTC camera decoder with atomic database-enforced duplicate scan prevention.
  • Dynamic JSONB Form Builder: Organizers add custom fields on-the-fly without database alterations.

2. System Design & Three-Tier Serverless Architecture

EventHub decouples presentation, compute, and persistence across three serverless tiers:

Tier Technology Role & Key Responsibilities
Tier 1: Client React 18 + Vite (Tailwind CSS) Single Page Application (SPA) served via Vercel Edge CDN with sub-50ms worldwide asset delivery. Integrates html5-qrcode for WebRTC smartphone camera scanning.
Tier 2: Compute FastAPI (Python 3.12 ASGI) Serverless Lambda handler in AWS iad1. Executes Pydantic data validation, generates in-memory vector QR codes, and dispatches background emails.
Tier 3: Persistence Supabase PostgreSQL 17 Enterprise relational database with ACID capacity locks, JSONB column support, and connection pooling via IPv4 PgBouncer (Port 6543).
Tier 3: Delivery Brevo SMTP Relay Dispatches transactional email passes with inline embedded MIME/CID QR codes directly to attendee inboxes for free.

3. Relational Database Schema & Data Integrity

Built on PostgreSQL 17 via Supabase with relational integrity, foreign key cascading, and JSONB dynamic fields:

Core Entities Overview
  • profiles: Stores organizers and administrators (UUID primary key, full name, role, avatar URL).
  • categories: Taxonomy system (BigInt primary key, unique category name, unique URL slug).
  • events: Event metadata (Foreign key to profiles.id and categories.id, title, description, venue, start/end timestamps, seat capacity, admission fee, banner URL, status, and custom_fields JSONB array).
  • registrations: Ticket records. Crucial Viva Point: user_id is NULLABLE to allow guest checkouts. Stores attendee_name, attendee_email, amount_paid, form_responses (JSONB), and a unique indexed ticket_token.
  • attendance: Door verification records. Has a UNIQUE foreign key on registration_id, guaranteeing at the database engine level that a pass cannot be checked in more than once.
Database Fraud Prevention Rationale for Viva
Instead of encoding internal database IDs into QR codes, EventHub generates a high-entropy random string (ticket_token, e.g., TK-eZ3aG1Cu...). When scanned, the backend verifies that the token belongs to the event and executes an atomic insert into attendance. If scanned a second time, PostgreSQL raises a unique constraint violation, resulting in an HTTP 409 Conflict.

5. Critical Technical Challenges Solved

1. Deploying Full-Stack FastAPI + React on Vercel Serverless ($0 Cost)

Challenge: Traditional Python backends require persistent 24/7 servers (Gunicorn/Uvicorn on EC2/Railway/Render) incurring continuous monthly costs.

Solution: We wrapped FastAPI into an ASGI serverless handler inside api/index.py. Using vercel.json, requests to /api/(.*) are rewritten to the Lambda handler while static assets and / are served by Vercel's global CDN.

2. Supabase IPv6 vs. Vercel IPv4 Routing Issue

Challenge: Supabase direct database host (db.<ref>.supabase.co) only resolves IPv6 AAAA records. Vercel's serverless Lambdas in AWS iad1 operate on IPv4-only networks, resulting in immediate connection timeouts.

Solution: Routed all database connections through Supabase's IPv4 Transaction Pooler (aws-0-ap-south-1.pooler.supabase.com:6543), enabling seamless IPv4 database access.

3. PgBouncer Prepared Statement Collision with AsyncPG

Challenge: Python's asyncpg driver caches prepared statements by default (__asyncpg_stmt_1__). Because PgBouncer multiplexes connections across lambdas, asyncpg crashed with prepared statement already exists.

Solution: In backend/app/database/session.py, we explicitly disabled statement caching for PgBouncer: connect_args={"statement_cache_size": 0, "prepared_statement_cache_size": 0}.

4. Universal Inline QR Code Email Delivery

Challenge: Modern email clients (Gmail, Outlook) block external image URLs or route passes to spam.

Solution: The backend generates vector QR code PNG bytes in memory and embeds them as inline MIME Multipart Related CID attachments via Brevo SMTP relay, ensuring passes render immediately in all inboxes.

6. Technology Stack Justification (Viva Q&A)

Component Chosen Tech Why Chosen over Alternatives?
Backend FastAPI (Python) Native async/await concurrency for I/O; automatic Pydantic input validation; self-generating Swagger documentation. Far faster and lighter than Django/Flask.
Database PostgreSQL 17 Strict ACID transaction locks prevent ticket overselling; relational integrity handles tickets and attendance; native JSONB columns store dynamic form questions flexibly.
Frontend React 18 + Vite Modular component lifecycle, instant Vite HMR, and small production bundle size. Avoided heavy Next.js SSR overhead since the backend is decoupled.
Email Brevo SMTP Free 300 emails/day to any inbox without paid sandboxes or domain authentication gates.
